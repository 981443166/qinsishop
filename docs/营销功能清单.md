> 口径：以 APK 内 H5 路由、模板、菜单常量（`MenuConstant`）与原生 SDK 为依据。
> 统计：App 自身归入营销的菜单 **19 个**；相关二级页面/弹窗约 **150+** 个模板；

## 10. 营销相关的原生 SDK

| SDK | 用途 | 风险 |
|---|---|---|
| `jpush-phonegap-plugin` | 推送（营销推送 + 订单通知混用） | 不能一刀切，需区分消息类型 |
| `cordova-plugin-wechat` / `qqsdk` | 微信/QQ 登录、分享 | 可能耦合微信登录，删除前需确认 |
| `cordova-alipay-base` | 支付（非营销） | 保留 |
| `Umeng` | 渠道/统计 | 可保留 |
| `cordova-plugin-x-socialsharing` | 系统分享（海报/链接） | 营销分享入口 |

## 12. 删除风险

1. **收银台价格**：优惠券、积分抵现、限时折扣嵌在 `sale` 流程里，只删入口不改算价会出现“金额对不上/提交失败”；
2. **历史订单**：老订单带有优惠/券字段，详情渲染要兼容；
3. **会员资产**：储值余额、积分是账务数据，删入口前要决定“只读保留/迁移/清零”；
4. **菜单是静态 JS + 权限位**：只删模板会导致菜单还在、点进去 404，必须同时删菜单项与路由；
5. **微信登录**：`cordova-plugin-wechat` 同时用于登录与分享，不能直接卸载；
6. **推送**：极光同时承载订单/审核通知，营销推送需按消息类型过滤，而不是删 SDK。

## 13. 建议的删除层次（后续执行）

| 层 | 动作 | 影响 |
|---|---|---|
| L1 | 隐藏 19 个营销菜单项 | 用户看不到，代码仍在，最安全 |
| L2 | 删除对应路由 + 模板 + 静态菜单常量 | 减小包体，入口彻底消失 |
| L3 | 清理交易内营销（券/折扣/积分抵现/分享/智能短信） | 需改算价与订单展示，风险最高 |
| L4 | 服务端关闭营销权限/接口 | 防止旧版本客户端继续调用 |
| L5 | 移除营销 SDK（推送/分享） | 需重新编译原生，风险高 |
