# 盘点撤销修复说明

> 问题：在「盘点历史」里点某张盘点单的“撤销”，实际撤销的是**最新一张**盘点单，而不是当前这条。
> 修改文件：`assets/www/js/app.min.js`（`StoreDetailCtrl`）

---

## 1. 原因

原逻辑在撤销前先调 `getLastStoredOrder.ac` 取“最后一张盘点单”：

- 若返回的单号 == 当前单号，才允许撤销当前单；
- 否则弹窗“仅支持撤销最后一张盘点单,是否需要去撤销最后一张盘点单?”，确认后把 `orderNo` 改成最后一张并重新加载，等于把用户带到最新单去撤销。

所以从历史列表进入任意旧单，撤销动作都会落到最新单上。

## 2. 修复

`$scope.destroyStoreOrder` 改为直接撤销当前路由参数对应的单据：

1. 不再调用 `getLastStoredOrder.ac`；
2. 用当前单据的 `updateTime` 做 7 天校验（超 7 天提示“不支持撤销”）；
3. 确认弹窗文案改为“是否确认撤销该单据?”；
4. 确认后直接调用 `destroyStoreOrderServe()`，传当前 `orderNo`。

撤销成功后仍会刷新操作记录、列表缓存和首页库存缓存，与原行为一致。

## 3. 已知限制

如果后端 `destroyStoreOrder.ac` 仍校验“只能撤销最后一张盘点单”，客户端放开后点旧单撤销会收到服务端错误提示。此时需要后端同步放开限制，客户端无需再改。

## 4. 验证

| # | 步骤 | 预期 |
|---|---|---|
| 1 | 盘点历史 → 进入一张**非最新**盘点单 → 更多 → 撤销 | 撤销的是这张单，不是最新单 |
| 2 | 撤销后返回列表 | 该单状态变为已撤销，最新单不受影响 |
| 3 | 进入超过 7 天的盘点单撤销 | 提示“已超过7天，不支持撤销” |
| 4 | 撤销最新一张 | 与原来一致，正常撤销 |
| 5 | 撤销后首页库存、盘点列表 | 自动刷新 |
