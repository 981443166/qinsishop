# 盘点单 · 单品模式商品搜索优化 — 修改说明

> 目标包：`com.qinsilk.appUniverse` 5.31.5（versionCode 53105031）
> 修改范围：仅 H5 资源（AngularJS 微应用），**未改动** dex、so、Manifest、资源表。
> 修改日期：2026-11-21

---

## 1. 问题与根因

**现象**：盘点单 → 盘点明细 → 添加商品 → 单品模式，在搜索框输入内容时整页刷新（全屏 loading、分类跳回"全部"、列表清空重填、滚动回顶），而不是只刷新商品列表。

**根因**（原始代码）：

1. 搜索框 `ng-change` 直接调用服务端查询：`storeOrder.searchGoodsByKeyword(false)`，不是本地过滤；
2. 查询经 500ms 防抖后进入 `searchGoods()`，每次都：重置分类为 `all`、`page=1`、`lbSpinnerDialog.show(true)` 全屏遮罩、请求 `goodsListWithOrderDetailCount.ac`；
3. 返回后用 `data.optionList` **整体替换** `search.goodListForSearchKey`，列表的 `filterCat` 只认这份"最新结果集"，旧行瞬间全部不可见；
4. `finally` 中强制 `scrollTop('storeGoodModalCtrlScroll')`，滚动位置丢失。

因此输入 → 一次完整"服务端重查 + 全屏 loading + 结果集替换 + 回顶"，观感就是整页刷新。

| 编号 | 原始行 | 改动内容 | 目的 |
|---|---|---|---|
| JS-1 | 253103–253104 | 新增 `storeKeywordSearch` 判定与本次请求关键字快照 `storeRequestKey`；`isLoading` 仅在非关键字搜索时为 true；新增 `search.listSearching` | 关键字搜索不再整页 loading，且慢响应不会被误标成新关键字 |

| JS-5 | 253199–253203 | `scrollTop` 仅在非关键字搜索时执行；`finally` 里复位 `listSearching` | 输入/搜索不再回顶 |

| JS-7 | 254184 后 | 新增 `singleModeSearchTextCache`、`singleModeLocalMatch()`、`$scope.singleModeVisible()`、`$scope.onKeywordInput()` | 本地关键字过滤 + 输入分流 |
| JS-8 | 254272–254275 | `clearSearch()`：盘点单只清空关键字并复位 `serverResultKey`，不再发请求 | 清空即恢复本地列表 |

**JS-7 关键逻辑**

```js
$scope.singleModeVisible = function (good) {
  if (!$scope.search || $scope.search.orderType !== 'store') return true;   // 调拨单不接管
  var rawKey = $scope.search.goodKey || '';
  if (rawKey.trim() === '') return true;                                    // 空关键字：显示已加载
  if ($scope.search.serverResultKey === rawKey && $scope.search.resultSnMap)
    return !!$scope.search.resultSnMap[good.goodsSn];                       // 已搜过：以服务端结果为准
  return singleModeLocalMatch(good, rawKey.trim());                         // 输入中：本地匹配
};
```

- 本地匹配字段：`name`、`goodsSn`、`barCode`、`specs`、`helpCode`、`pinyin`、`propertyName`、`propertyValueName`（字段不存在时自动跳过），大小写不敏感；
- 首次匹配后按 `goodsSn` 缓存小写文本，避免每次 digest 重复拼接；
- **不缓存到商品对象上**，避免污染保存到服务端的 `goodsGroup` 数据。

## 4. 行为变化

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 输入关键字（逐字） | 500ms 后发请求；全屏 loading；分类重置"全部"；列表清空重填；回顶 | **0 请求**；仅本地过滤；分类/滚动/焦点保持不变 |
| 停顿后继续输入 | 每次都重新请求 | 不再请求 |
| 回车 / 键盘搜索键 | 服务端全库搜索（全屏 loading + 回顶） | 服务端全库搜索；**列表区**提示"正在搜索全部商品…"，不回顶、不重置分类 |
| 点击"查询全部分类" | 防抖后服务端搜索 | 立即服务端搜索（同上表现） |
| 点击输入框 ×（清空） | 清空后立刻再发一次请求 | 清空即恢复本地列表，**不发请求** |
| 本地无匹配 | 空态 + "查询全部分类" | 同左；点击后走全库搜索 |
| 加载更多（触底） | 追加分页，列表按最新结果集过滤 | 追加分页，本地过滤覆盖全部已加载页 |
| 多规格模式（商品模式） | 服务端搜索 | **完全不变** |
| 调拨单选择商品 | 服务端搜索 | **完全不变**（`orderType !== 'store'` 时走原逻辑） |

> 空关键字时，列表展示"当前已加载的 `storeOrder.goodsGroup`"（与订单明细同源），已加购商品仍由原有 `goodsIsShow` 隐藏；切换分类仍按原逻辑清空并重查。

## 5. 兼容性与已知限制

1. **本地匹配字段有限**：商品的本地对象只含 `name/goodsSn/specs` 等字段；若商品靠**别名、助记码、条码**才能命中，且这些字段未随列表返回，则输入时不会命中，需要回车/"查询全部分类"走服务端搜索（服务端返回后以结果集为准）。
2. **结果集缓存按"关键字原文"匹配**：输入变化即切回本地过滤；重新输入相同关键字会复用该次服务端结果（同关键字，语义一致）。
3. **未启用 `track by`**：`ng-repeat` 未加 `track by good.goodsSn`，避免极端情况下重复 `goodsSn` 触发 Angular 重复键异常；行对象未被重建，输入过滤仍只增删行、不重建整表。
4. **`app.min.js` 为压缩产物**：补丁以行号 + 原文断言定位，升级新版本时需重新评估行号。
5. **未改动后端接口**：`goodsListWithOrderDetailCount.ac` 等契约不变。

1. 确认单品模式下 `goodsSn` 唯一后，为列表加 `track by good.goodsSn`，进一步减少 DOM 操作；
2. 若服务端列表接口能返回 `barCode/助记码`，补入本地匹配字段，减少"必须回车"的场景；

4. 将"已加载集合"与"服务端结果集"的切换状态显式化（当前用 `serverResultKey` 隐式表达）。
